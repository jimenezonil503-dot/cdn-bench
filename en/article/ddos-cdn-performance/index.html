How Fast Is a Protected CDN? Nodes, Routes, Security and Origin Performance

Separate DNS, connections, cache delivery, origin access and application processing to judge acceleration. Learn what TTFB, P95 and hit ratio can actually establish.

CDN Bench editorial · 2026-10-14 · Updated 2026-10-147 min read
In this article
  1. Acceleration benefits depend on the path
  2. Define metric boundaries and samples
  3. Include cold-cache and update costs
  4. Protocols and PoP counts are not a performance formula
  5. Measure legitimate users during mitigation
  6. Locate the layer responsible for slow requests

Acceleration benefits depend on the path

A protected CDN can move cacheable content closer to users and filter traffic before it reaches the origin. It does not guarantee faster dynamic responses. Edge placement, routes, cache state, mitigation routing and application processing interact. Evaluate CDN5 where appropriate using actual workloads, not BGP/CN2 labels as latency evidence.

Define the outcome: faster reading, completed downloads or fewer transaction timeouts. Throughput and dynamic TTFB describe different experiences. A lower average with more failures is not improvement. Security challenges and reconnects also affect legitimate task completion.

Define metric boundaries and samples

Browser, edge and origin measurements may use different boundaries. State whether TTFB includes redirects or connection setup. P95 is a percentile within defined samples, not 95% availability or maximum latency. Small samples, success-only selection and mixed regions can distort interpretation.

Include cold-cache and update costs

Hits return from the edge; misses also require origin processing. An illustrative 90% request hit rate does not imply a 90% speed improvement, because payloads, regions and response times differ. Byte and request hit ratios can diverge substantially.

RFC 9111 defines freshness and reuse; CloudFront cache-key policies explain grouping dimensions. Unnecessary parameters can fragment caches, while removing identity dimensions can break isolation. Test expiry, purging and simultaneous misses without caching transactions merely to improve a metric.

Protocols and PoP counts are not a performance formula

HTTP/2 improves connection utilization through multiplexing, but TCP loss can affect streams. HTTP/3 uses QUIC, with benefits dependent on clients and UDP paths. Compare new/reused connections, mobility and fallback rather than promising a fixed percentage gain.

PoP count does not establish the endpoint your users receive. DNS, Anycast and peering govern placement; origin distance affects misses. A nearby Hong Kong edge with a distant origin can still serve slow dynamic requests. Measure paths before selecting regional origins, edge logic or optimized origin transport.

Measure legitimate users during mitigation

Challenges, limits, connection handling and mitigation changes can alter legitimate latency. Distinguish malicious blocks, false positives and completed tasks. For APIs, callbacks and WebSocket, observe retries, disconnects and state recovery rather than applying browser verification universally.

Ask CDN5 and other candidates about protected routing, origin access and over-limit handling. Advertised capacity does not establish attack-period P95. Only authorized, documented exercises support corresponding results. Without them, present capability sources and an evaluation plan, as this article does.

Locate the layer responsible for slow requests

Start with resolution for DNS failures, carrier/address-family paths for connection failures, and cache/origin/application timing for slow first bytes. For slow completion, check size, loss and throughput. Correlate 502/504 with origin logs; inspect policies for challenges or 429. Similar symptoms do not imply one cause.

Build a baseline using the lab and Hong Kong origin guide. Compare consistent windows and preserve configurations alongside business outcomes. A useful improvement claim identifies users, request types and periods, including paths that remain slow.

Record corporate proxies and VPNs, which alter paths. Keep access networks consistent rather than attributing proxy-versus-direct routing differences to providers.
